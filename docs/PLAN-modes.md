## 1. 지금 코드의 한계 (먼저 고쳐야 할 것)

현재 구조를 읽어 보면 새 기능 대부분이 아래 다섯 가지 가정에 막힙니다.

| 가정 | 위치 | 막히는 기능 |
|---|---|---|
| 판 크기가 상수(`COLS=8, VIS=14`, `FW/FH/CS`도 상수) | `index.html` 517~521행 | 6×12, 타이니 뿌요, 퓨전(10열) |
| 대전은 항상 2명(`f.opp` 한 명, `fields[0..1]`, 시리즈 `me/op`, 서버 방 `players` 2명) | `build()`, `attack()`, `update()`의 승패 판정, `server.js` | 3~4인, 파티, 랭크전 |
| 규칙이 `Field`/`TField` 안에 직접 들어 있음(연쇄 점수·방해뿌요·마진 타임) | `beginPop()`, `attack()`, `endChain()`, `TField.lock()` | 피버·빅뱅·파티·스왑·퓨전 |
| 게임 이벤트가 온라인 전송(`gsend`)에만 쓰임 | `lock()`, `dropGarbage()`, `TField.lock()` | 리플레이 |
| JS가 `index.html` 한 파일(2860줄)에 모두 있음 | `public/index.html` | 전부(파일이 2~3배로 커짐) |

그래서 **0단계(기반 정리)** 를 먼저 하고, 그 위에 기능을 얹습니다.

## 2. 0단계 — 기반 정리 (기능 변화 없음)

### 2-1. 파일 나누기
- `public/js/` 아래로 나눔: `core.js`(상수·RNG·사운드), `puyo.js`(Field), `tetris.js`(TField), `rules/*.js`(모드별 규칙), `ai/*.js`, `ui.js`(메뉴·설정·기록), `net.js`, `replay.js`, `main.js`.
- ES 모듈이 아닌 **일반 `<script src>`** 로 읽어서 `index.html`을 파일로 바로 열어도(서버 없이) 지금처럼 동작하게 유지.
- `server.js`에 `/js/*`, `/assets/*` 정적 파일 제공 추가(경로 탈출 막기).

### 2-2. 판 설정 객체 `BoardCfg`
```js
// 뿌요 판 크기는 '판(대전) 단위' 설정. 한 판 안의 뿌요 플레이어는 모두 같은 크기를 씀
game.board = { cols: 6, vis: 12, hidden: 1, cs: 46 };   // 원작
```
- `COLS / VIS / ROWS / CS / FW / FH / SP / R / BW`를 `let`으로 바꾸고 `applyBoard(cfg)`가 다시 계산.
- 화면 높이(`FH`)를 기준으로 `CS = FH / vis`로 맞춰서 판 크기가 바뀌어도 전체 레이아웃은 그대로. (6×12면 `CS≈46.7`, `FW=280`. 테트리스 판 `10×28=280`과 폭이 같아져 오히려 깔끔함)
- AI 시뮬레이션(`simResolve`, `heightsOf`, `planAI`)은 이미 `COLS/ROWS`를 참조하므로 상수만 바뀌면 따라옴. `danger` 기준(`VIS-3`)도 비율로 바꿈.

### 2-3. N명 구조
- `f.opp` → `f.target()`(공격 대상 고르기) + `game.opponentsOf(f)`.
- 승패: "한 명 빼고 다 죽으면 끝" + 순위 기록(`f.place`).
- 시리즈 점수: `series = { wins: [0,0,0,0], to }`.
- 레이아웃 함수 `layout(n)`: 1명(연습) / 2명(지금 그대로) / 3~4명(판을 축소 배치, 아래 4장 참고).
- `game.inp`를 4개로 늘리고 패드 1~4번을 플레이어 1~4에 연결.

### 2-4. 규칙(Rule) 훅
모드마다 바뀌는 부분만 갈아 끼우는 객체로 뺍니다.
```js
const RULES = {
  tsu:     { ... },   // 지금 규칙(기본)
  fever:   { ... },
  bigbang: { ... },
  party:   { ... },
  swap:    { ... },
  fusion:  { ... },
};
// 훅 예시
rule.board()                 // 판 크기
rule.nextPiece(f)            // 다음 조각(피버: 3·4개짜리 조각, 파티: 아이템)
rule.chainStep(f, info)      // 연쇄 단계 점수 → 공격량
rule.onChainEnd(f)           // 피버 게이지, 전멸 보너스
rule.onGarbage(f, n)         // 방해뿌요 떨어뜨리는 방식
rule.tick(dt)                // 스왑 타이머, 파티 제한 시간
rule.isOver(fields)          // 승패/종료 조건(빅뱅 HP, 파티 시간 종료 점수)
rule.drawOverlay(c, f)       // 모드 전용 표시
```
지금 규칙을 그대로 `RULES.tsu`로 옮겨서 **동작이 같은지 먼저 확인**한 뒤에 다른 규칙을 추가합니다.

### 2-5. 이벤트 버스
- 지금 `gsend({t:'lock'...})`, `gsend({t:'garb'...})`, `tlock`, `tgarb`, `atk`, `off`, `dead`를 **`emit(fieldIndex, ev)`** 한 곳으로 모음.
- `emit`은 ① 온라인이면 전송 ② 리플레이 녹화 중이면 기록. → 리플레이가 거의 공짜로 나옴(7장).
- 이벤트에 `pi`(플레이어 번호)와 `ts`(시작 후 ms)를 붙임. 3~4인 온라인에서도 그대로 씀.

### 2-6. 저장 데이터 버전
- `puyo-stats-v1` → `v2`로 올리고 `migrate()` 작성. 새 항목: 모드별 기록, 캐릭터 해금, 어드벤처 진행, 리플레이 목록, 판 크기 설정.

## 3. 1단계 — 바로 넣을 수 있는 것

### 3-1. 원작 크기(6×12) 뿌요판 옵션
- 설정(⚙) 또는 AI 대전/대전 화면 위쪽 바에 **판 크기: 원작 6×12 / 넓게 8×14** 세그먼트 추가. 기본값은 원작 6×12 권장.
- 원작 규칙 맞춤
  - 사망 칸: 3열 12단(`SP = 2`) — 지금 공식 `floor((COLS-1)/2)`가 6열에서 2가 되어 그대로 맞음.
  - 숨김 13단: 지금 `ROWS = VIS + 1`과 같음. 14단(회전용 가상 칸)은 회전 판정에서만 허용.
  - 방해뿌요 한 번에 최대 30개(5줄) = 지금 값과 같음.
- 온라인: 서버 `start` 메시지에 `board`를 넣고, 방 만든 사람 설정을 따름. 빠른 매칭은 같은 판 크기끼리만 매칭.
- 기록: 판 크기별로 최고 연쇄를 따로 저장.

### 3-2. T스핀을 쓰는 테트리스 CPU
지금 CPU(`TField.planAI`)는 "모든 열×회전에서 하드드롭한 자리"만 평가해서, 회전으로 밀어 넣는 T스핀 자리는 아예 후보에 없습니다.

1. **도달 가능한 자리 탐색**: 시작 위치에서 좌우 이동·회전(SRS 킥 포함)·한 칸 내리기를 BFS로 돌려 땅에 닿는 모든 상태를 모음. 마지막 동작이 회전인지, 몇 번째 킥이었는지도 저장 → 기존 `tspinType()`로 T스핀 여부 판정.
2. **경로 저장**: 각 자리까지의 키 입력 순서를 같이 저장하고 `aiAct`가 그 순서대로 입력(지금은 "회전 맞추고 → 열 맞추고 → 드롭"만 가능).
3. **평가 추가**
   - T스핀 더블/트리플 실행: 큰 가산점(`+공격량 × 가중치`), B2B 유지 가산.
   - **T 구멍 만들기**: 놓은 뒤 판에 "T가 들어갈 3코너 구멍 + 지붕(overhang)" 모양이 생기면 가산(TSD 슬롯 패턴 몇 개를 템플릿으로 검사).
   - 홀드에 T를 보관하는 것에 가산, 슬롯이 있는데 T를 엉뚱하게 쓰면 감점.
   - 다음 5개를 보고 1수 앞(현재+다음 조각)까지 탐색 — 어려움 이상만.
4. **난이도**: `AI_TETRIS`에 `tspin: 0~1`(T스핀 의지), `lookahead`, `finesse` 추가. 쉬움=0, 보통=TSD만 가끔, 어려움=TSD/TST 적극, 새 단계 **"최강"** 추가 고려.
5. 성능: 상태 수가 조각당 수백 개 수준이라 매 조각마다 계산해도 충분. 1수 앞 탐색은 후보 상위 10개만 펼침.

### 3-3. 리플레이
0단계 이벤트 버스를 쓰면 됩니다.
- **녹화 내용**: `{ver, seed, board, rule, players:[{style, char, name}], events:[{ts, pi, ...}] }`. 이벤트에는 이미 격자 스냅샷(`g`)이 들어 있어서 재생이 어긋나지 않음. 떨어지는 조각의 움직임은 `st` 이벤트(지금처럼 50ms 간격)를 같이 기록.
- **재생**: 모든 판을 지금의 "원격(remote) 판"으로 만들고 이벤트를 시간대로 넣음 — 온라인 상대 화면 재현 코드(`pump`, `applyEvent`)를 그대로 재사용.
- **조작**: 재생/일시정지, 0.5×·1×·2×·4×, 처음으로. 되감기는 처음부터 빨리 감기로 처리.
- **저장**: 최근 10판 자동 저장(`localStorage`, 압축 없이 판당 수십 KB 예상 → 넘치면 오래된 것부터 삭제), '즐겨찾기'는 삭제 안 함, `.puyoreplay`(JSON) 파일로 내보내기/불러오기.
- 메뉴: **내 정보 → 리플레이** 탭.

## 4. 2단계 — 3~4인 대전

| 항목 | 내용 |
|---|---|
| 화면 | 3~4명은 판을 0.6~0.7배로 줄여 가로로 배치. 내 판만 크게(1.0배) + 나머지 작게 하는 배치도 선택 |
| 공격 대상 | 기본: **나를 마지막으로 공격한 사람 → 없으면 가장 높이 쌓인 사람**. 옵션: 랜덤 / 순환 / 전원에게 나눠서 |
| 방해 표시 | 각 판 위에 받을 방해뿌요 + 누가 보냈는지 색 표시 |
| 탈락 | 탈락한 판은 회색 처리, 그 사람에게 쌓인 공격은 없어짐. 마지막 1명이 승리, 순위 기록 |
| 조작 | 로컬: 키보드 2명 + 패드 2개 등 조합. 빈 자리는 CPU로 채움 |
| 온라인 | 서버 방 정원 2 → 2~4. `ready` 판정을 "방 안의 모든 사람"으로. 방장이 시작 버튼. 메시지에 `pi` 추가, 서버는 방 안 다른 모두에게 중계 |
| 스타일 혼합 | 뿌요·테트리스 섞여도 됨. 공격 변환은 지금의 뿌요↔테트리스 공식을 대상마다 적용 |

순서: CPU 3~4인(오프라인) → 로컬 → 온라인.

## 5. 3단계 — 뿌요 전용 모드

### 5-1. 피버 엔진 (엔드리스 피버·빅뱅의 공통 바탕)
원작 「뿌요뿌요 피버」 규칙
- 상쇄할 때마다 **피버 게이지**가 1칸씩(7칸) 참. 다 차면 **피버 모드**: 원래 판을 잠시 치우고 미리 짜인 연쇄 씨앗판이 떨어짐. 한 뿌요만 놓아 연쇄를 터뜨리면 다음 씨앗판(연쇄 수 +1/-2)으로 바뀌고, 피버 시간(기본 15초)이 끝나면 원래 판으로 복귀.
- 다음 조각이 2개짜리만이 아니라 **3개·4개짜리(대형) 조각**도 나옴.
- 연쇄 점수표(`CHAIN_POWER`)가 다름 → 피버 전용 표.

필요한 작업
- `rule.nextPiece()`가 2~4칸 조각을 줄 수 있게 `Field`의 조각 표현을 "쌍"에서 "칸 목록"으로 일반화(회전·충돌·그리기·AI 포함). — 가장 큰 작업
- 연쇄 씨앗판 데이터: `data/fever-chains.json`(판 크기별, 3~15연쇄). 직접 만들거나 생성기로 만들고 검증 스크립트(`simResolve`로 실제 연쇄 수 확인) 작성.
- 원래 판 보관/복귀, 피버 타이머 표시.

### 5-2. 엔드리스 피버 (1인)
- 피버 모드만 계속되는 연습 모드: 제한 시간 안에 씨앗판을 연속으로 터뜨려 점수. 시간 보너스는 연쇄 수에 비례.
- 기록: 최고 점수, 최고 연쇄. 메뉴: AI 대전 → 연습(뿌요뿌요)에 하위 메뉴 추가(지금 테트리스 연습 화면 `sc-solo`와 같은 구조).

### 5-3. 타이니 뿌요
- 작은 뿌요로 **판이 넓고 높은** 모드. 2-2의 `BoardCfg`만 바꾸면 대부분 됨(`cs`가 작아짐).
- 크기 후보: 원작 수치는 확인 필요. 우선 **12×24**로 잡고 테스트 후 조정. 방해뿌요 최대치·한 줄 수도 판 폭에 맞춤.
- 그리기: 뿌요 반지름·눈 그림이 `R`에 비례하는지 확인(작은 크기에서 선 두께 보정).
- 대전(CPU/로컬/온라인)과 연습 모두 지원.

### 5-4. 빅뱅
원작 「뿌요뿌요 테트리스」 빅뱅: 양쪽에 같은 연쇄 씨앗판(테트리스는 같은 줄 지우기 퍼즐)이 주어지고, **더 빨리·더 크게** 터뜨린 쪽이 상대의 **체력(HP)** 을 깎음. HP가 0이 되면 패배.
- 피버 씨앗판 데이터 재사용 + 테트리스용 퍼즐판 데이터(`data/bigbang-tetris.json`) 새로 작성.
- 라운드: "둘 다 판을 끝내면 비교 → 차이만큼 데미지 연출" 반복.
- 방해뿌요/줄 공격은 없음 → `rule.chainStep`이 공격 대신 점수만 계산.

## 6. 4단계 — 뿌요뿌요 테트리스 대전 규칙

### 6-1. 스왑
- 일정 시간(원작 25초)마다 **뿌요판 ↔ 테트리스판이 번갈아** 바뀜. 각 플레이어는 두 판을 모두 가지고, 안 쓰는 판은 멈춤.
- 쌓인 공격은 바뀐 판으로 넘어감(뿌요 방해 ↔ 테트리스 줄 변환은 지금 공식 사용). 어느 쪽 판이든 죽으면 패배.
- 구현: 플레이어 = `{ puyo: Field, tetris: TField, active }` 묶음(`SwapSlot`). 화면은 활성 판을 크게, 쉬는 판을 작게. 전환 때 회전 연출 + 3초 전 경고.

### 6-2. 파티
- 제한 시간(원작 2분) 동안 **점수 경쟁**. 판에 **아이템**이 나타나 터뜨리거나 줄을 지우면 발동.
- 아이템 예: 상대 방해 +, 내 판 정리, 상대 조작 반전, 상대 다음 조각 숨기기, 내 판 색 섞기, 무적 등. (원작 아이템 목록은 확인 후 맞춤. 우선 6종으로 시작)
- 죽어도 탈락이 아니라 판이 비워지고 점수 감점 → 시간이 끝났을 때 점수 순위.
- 3~4인과 궁합이 좋으므로 **4인 지원 후에** 넣음.

### 6-3. 퓨전
- 폭 10의 **한 판에 뿌요 쌍과 테트리스 조각이 함께** 떨어짐. 테트리스 조각이 뿌요 위치에 놓이면 뿌요가 조각 위로 밀려 올라감. 뿌요는 4개 연결로, 테트리스 조각은 줄 완성으로 지워짐.
- 지금의 `Field`/`TField`를 섞을 수 없어서 **새 판 클래스 `FusionField`** 가 필요. 격자 한 칸이 `{kind: 'puyo'|'mino'|'garbage', ...}`.
- 원작 세부 규칙(줄 판정에 뿌요를 세는지, 조각이 나오는 순서, 공격 계산)은 자료 확인 후 확정. **가장 어렵고 리스크가 커서 마지막 순서**.

## 7. 5단계 — 메타 기능

### 7-1. 캐릭터
- `data/characters.js`: `{ id, name, color, portrait(그리기 함수), voice(효과음 음높이/패턴), cutin 대사(연쇄 단계별), dropPattern, feverSet, ai(CPU 성격) }`.
- 그림은 지금처럼 **캔버스로 직접 그림**(외부 이미지 없음). 우선 8명.
- 게임에 주는 영향
  - 연쇄할 때 컷인 대사(1~5연쇄 이상 단계별) + 음성 대용 효과음.
  - **드롭 패턴**(피버·퓨전에서 큰 조각이 나오는 순서)과 **피버 씨앗판 세트**가 캐릭터마다 다름(원작 방식).
  - CPU 캐릭터마다 성격(속공형/대연쇄형/T스핀형).
- 선택 화면: 대전 시작 전 캐릭터 고르기(로컬 4명 동시 선택 가능), 온라인은 `start` 메시지에 캐릭터 포함.

### 7-2. 어드벤처
- 스테이지를 이어서 깨는 1인 모드. 스테이지 = `{ 상대 캐릭터, 규칙(tsu/fever/swap/…), 내 스타일, 판 크기, 클리어 조건(승리/일정 점수/몇 연쇄), 대사 }`.
- 1장 10스테이지 정도로 시작해 장 단위로 추가. 각 장이 새 모드를 소개하는 튜토리얼 역할(예: 3장 피버, 5장 스왑).
- 진행·별점(클리어 시간·연쇄 기준 별 3개) 저장, 클리어 보상으로 캐릭터 해금.
- 대사창은 HTML 오버레이(캐릭터 초상화 캔버스 + 글자 한 자씩 표시, 넘기기).
- **캐릭터와 각 모드가 먼저 있어야** 해서 거의 마지막.

### 7-3. 랭크전
지금 서버는 메시지 중계만 하고 계정이 없어서 아래가 필요합니다.
- **플레이어 식별**: 처음 접속할 때 서버가 무작위 토큰을 발급 → 브라우저에 저장. (계정·비밀번호 없음. 브라우저를 바꾸면 새 사람)
- **레이팅 저장**: 서버에 `data/ranks.json`(또는 SQLite). 레이팅 방식은 Glicko-2 권장(적은 판수에서도 안정적), 초기 1500.
- **매칭**: 레이팅이 가까운 사람끼리. 기다릴수록 허용 범위를 넓힘(±100 → 10초마다 +50).
- **규칙 고정**: 2선승, 원작 6×12, 통상 규칙. 스타일은 자유(뿌요/테트리스 각각 별도 레이팅).
- **결과 판정**: 지금은 각자 자기 판을 계산하므로 속이기 쉬움. 1차로는 두 클라이언트가 보낸 결과가 일치할 때만 반영, 불일치·중도 이탈은 이탈한 쪽 패배. (완전한 부정 방지는 서버가 이벤트를 검증해야 해서 범위 밖으로 둠)
- 화면: 등급(브론즈~마스터) 아이콘, 시즌 순위표(상위 100명), 내 레이팅 변화 그래프.
